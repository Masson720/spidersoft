# Ansible Playbooks

В проекте SpiderSoft Infrastructure используются три Ansible-плейбука для проверки состояния сервера и управления доступом контрольной машины.

## 01-gather-facts.yml

**Назначение:** аудит и проверка текущей конфигурации SpiderSoft-сервера.

Плейбук собирает системную информацию и проверяет соответствие сервера требованиям проекта.

Проверяет:

* hostname, ОС, версию ядра и архитектуру;
* количество CPU и объём оперативной памяти;
* использование дискового пространства;
* наличие пользователя `devops`;
* настройки SSH:

  * `PermitRootLogin`;
  * `PasswordAuthentication`;
  * SSH-порт;
* правила `DOCKER-USER` в iptables;
* наличие ALLOW-правила для контрольной машины;
* разрешённые Docker-порты;
* наличие общего `DROP`-правила;
* правильный порядок правил `ALLOW → DROP`.

В конце выводит сводный **compliance-отчёт**.

**Тип:** только проверка, конфигурацию сервера не изменяет.

---

## 02-firewall-control-ip.yml

**Назначение:** управление доступом контрольной машины к Docker-сервисам SpiderSoft.

Плейбук:

* проверяет наличие `control_ip`;
* проверяет наличие списка разрешённых портов;
* удаляет старое управляемое правило;
* создаёт актуальное правило `ALLOW` для IP контрольной машины;
* ограничивает доступ только TCP-портами из `spidersoft_monitoring_ports`;
* добавляет правило в начало цепочки `DOCKER-USER`;
* использует комментарий `SPIDERSOFT_CONTROL_ALLOW` для дальнейшего управления правилом.

Разрешённые порты хранятся в `inventory/group_vars/all.yml`, поэтому они не дублируются в самом плейбуке.

**Тип:** изменяет конфигурацию firewall.

---

## 03-check-control-ip.yml

**Назначение:** проверка IP-адреса контрольной машины перед изменением firewall.

Плейбук выполняется локально на контрольной машине и определяет, с какого IP она фактически обращается к SpiderSoft-серверу.

Проверяет:

* текущий source IP контрольной машины;
* IP, указанный в `control_ip`;
* адрес SpiderSoft-сервера.

Если IP совпадает — выводит `OK`.

Если IP изменился — выводит предупреждение о необходимости обновить firewall allowlist.

**Тип:** только диагностика, firewall не изменяет.

---

## Общая схема

```text
Контрольная машина
       │
       ├── 03-check-control-ip.yml
       │       │
       │       └── Проверяет текущий IP
       │
       └── 02-firewall-control-ip.yml
               │
               └── Обновляет DOCKER-USER
                       │
                       ▼
              SpiderSoft-сервер
                       │
                       └── 01-gather-facts.yml
                               │
                               └── Проверяет итоговую конфигурацию
```

Таким образом:

**03 → обнаружить изменение IP**

**02 → применить новый IP в firewall**

**01 → проверить итоговое состояние сервера**
