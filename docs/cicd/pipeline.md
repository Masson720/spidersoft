    2. Установка зависимостей:

============================================================
                 🐳 JOB: DOCKER-BUILD
============================================================

Задача:

    Собрать Docker-образ API и опубликовать
    его в GitHub Container Registry.


Условие запуска:

    test должен завершиться успешно.


Основной image:

    spidersoft-api


Registry:

    ghcr.io/masson720/spidersoft-api


Основные этапы:

    1. Авторизация в GHCR.
    2. Сборка Docker image.
    3. Добавление тегов.
    4. Push в GHCR.


Используется:

    GITHUB_TOKEN


Необходимые permissions:

    packages: write


============================================================
                    🏷️ TAGGING
============================================================

Один Docker image получает несколько тегов.


SHA:

    <SHA>

    Уникальный идентификатор Git commit.

    Пример:

        a1b2c3d4e5f6


    SHA является immutable.


main:

    main

    Последняя успешная сборка
    из ветки main.


latest:

    latest

    Указатель на последнюю версию.


Пример:

    ghcr.io/masson720/spidersoft-api:a1b2c3d4

    ghcr.io/masson720/spidersoft-api:main

    ghcr.io/masson720/spidersoft-api:latest


Использование SHA позволяет:

    - точно определить версию;
    - воспроизводить deployment;
    - выполнять rollback;
    - избежать неоднозначности latest.


============================================================
                    🚀 JOB: DEPLOY
============================================================

Задача:

    Обновить API-контейнер на SpiderSoft-сервере.


Условия:

    docker-build успешно завершён.

    Ветка:

        main


Runner:

    self-hosted


Основной скрипт:

    /opt/spidersoft/scripts/deploy-api.sh


Pipeline передаёт ему SHA образа.


Пример:

    /opt/spidersoft/scripts/deploy-api.sh a1b2c3d4e5f6


============================================================
                 🖥️ SELF-HOSTED RUNNER
============================================================

Для deployment используется self-hosted GitHub Actions
runner.

Runner установлен непосредственно на SpiderSoft-сервере.


Директория:

    /opt/actions-runner


Runner работает как системная служба.


Управление:

    ./svc.sh install
    ./svc.sh start


Проверка:

    ./svc.sh status


Основные преимущества:

    - deployment выполняется непосредственно на сервере;
    - не требуется SSH-подключение к серверу;
    - не требуется открывать SSH для GitHub Actions;
    - Docker доступен локально;
    - docker compose доступен непосредственно runner'у.


============================================================
                    🔐 СЕКРЕТЫ
============================================================

Для авторизации в GHCR используется:

    GITHUB_TOKEN


Token предоставляется GitHub автоматически.


Необходимое permission:

    packages: write


SSH_PRIVATE_KEY:

    Не используется для текущего deployment,
    поскольку runner является self-hosted
    и работает непосредственно на сервере.


Не хранить приватные ключи и credentials
непосредственно в репозитории.


============================================================
                    📄 DEPLOY SCRIPT
============================================================

Файл:

    /opt/spidersoft/scripts/deploy-api.sh


Скрипт принимает SHA образа:

    ./deploy-api.sh <SHA>


Пример:

    /opt/spidersoft/scripts/deploy-api.sh a1b2c3d4e5f6


Основная последовательность:

    1. Получение SHA.
             │
             ▼
    2. Pull Docker image из GHCR.
             │
             ▼
    3. Обновление .env.
             │
             ▼
    4. Установка API_IMAGE.
             │
             ▼
    5. docker compose up
             │
             ▼
    6. Force recreate контейнера.
             │
             ▼
    7. Проверка health.
             │
             ▼
    8. Сохранение текущего SHA.


Текущая версия сохраняется в:

    /opt/spidersoft/app/current-version


Healthcheck:

    Ожидание healthy
    Максимальное время: 30 секунд

============================================================
                    🟢 СТАТУСЫ
============================================================

GREEN:

    Все Jobs успешно завершены.
    Docker image опубликован.
    Deployment выполнен.


RED:

    Один из этапов завершился ошибкой.

    Следующий Job не запускается.


Зависимости:

    test
      │
      ▼
    docker-build
      │
      ▼
    deploy


Если test завершился ошибкой:

    docker-build не запускается.


Если docker-build завершился ошибкой:

    deploy не запускается.


============================================================
                    ⚠️ ОШИБКА DEPLOY
============================================================

Если deployment завершается ошибкой,
состояние контейнера зависит от момента сбоя.

Текущая реализация выполняет операции
последовательно и завершает скрипт при ошибке.

Перед изменением контейнера рекомендуется
проверять доступность нового image.


============================================================
                    🔙 ROLLBACK
============================================================

Текущую версию можно узнать:

    cat /opt/spidersoft/app/current-version


После этого можно выполнить deployment
предыдущей версии вручную:

    /opt/spidersoft/scripts/deploy-api.sh <SHA>


Пример:

    /opt/spidersoft/scripts/deploy-api.sh a1b2c3d4e5f6


Rollback использует тот же deployment script,
но с SHA предыдущего Docker image.
