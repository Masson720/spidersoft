============================================================
                  🕷 SPIDERSOFT BACKUP 🕷
============================================================

В SpiderSoft используется собственный Bash-скрипт
для резервного копирования важных данных.

Основная задача:

    - создавать архивы критических данных;
    - сохранять конфигурации;
    - сохранять данные приложения;
    - обеспечивать возможность восстановления.


============================================================
                    📜 BACKUP SCRIPT
============================================================

Файл:

    /opt/spidersoft/scripts/backup.sh


Формат архива:

    tar.gz


Имя файла:

    <directory>-<date>_<time>.tar.gz


Пример:

    app-2026-08-20_14-30-00.tar.gz


============================================================
                    🚀 ИСПОЛЬЗОВАНИЕ
============================================================

Бэкап директории по умолчанию:

    /opt/spidersoft/scripts/backup.sh


По умолчанию архивируется:

    /opt/spidersoft/app


Результат сохраняется в:

    /opt/spidersoft/backups/


============================================================
              📁 БЭКАП ПРОИЗВОЛЬНОЙ ДИРЕКТОРИИ
============================================================

Директория передаётся первым аргументом.


Пример:

    /opt/spidersoft/scripts/backup.sh /etc


В данном случае будет создан архив:

    etc-YYYY-MM-DD_HH-MM-SS.tar.gz


Ещё один пример:

    /opt/spidersoft/scripts/backup.sh /opt/spidersoft/docker


Это удобно для запуска через cron.


============================================================
                    📂 ХРАНИЛИЩЕ
============================================================

Все резервные копии хранятся здесь:

    /opt/spidersoft/backups/


Пример:

    /opt/spidersoft/backups/

    ├── app-2026-08-20_14-30-00.tar.gz
    ├── app-2026-08-19_02-00-00.tar.gz
    ├── etc-2026-08-18_00-00-00.tar.gz
    └── docker-2026-08-17_00-00-00.tar.gz


Проверить созданные бэкапы:

    ls -lh /opt/spidersoft/backups/


Проверить размер каталога:

    du -sh /opt/spidersoft/backups/


============================================================
                    🗂️ СТРУКТУРА
============================================================

    /opt/spidersoft/
    │
    ├── app/
    │   └── данные приложения
    │
    ├── backups/
    │   └── *.tar.gz
    │
    └── scripts/
        └── backup.sh


Важно:

    backups/ не должна находиться внутри директории,
    которую архивирует backup.sh.

Иначе архив может включать сам себя
или предыдущие резервные копии.


============================================================
                    🔍 ПРОВЕРКА АРХИВА
============================================================

Посмотреть содержимое архива:

    tar -tzf /opt/spidersoft/backups/app-2026-08-20_14-30-00.tar.gz


Проверить целостность gzip-архива:

    gzip -t /opt/spidersoft/backups/app-2026-08-20_14-30-00.tar.gz


Посмотреть размер:

    ls -lh /opt/spidersoft/backups/*.tar.gz


============================================================
                    ♻️ ВОССТАНОВЛЕНИЕ
============================================================

Создать временную директорию:

    mkdir -p /tmp/spidersoft-restore


Распаковать архив:

    tar -xzf \
    /opt/spidersoft/backups/app-2026-08-20_14-30-00.tar.gz \
    -C /tmp/spidersoft-restore


Перед восстановлением рекомендуется:

    1. Проверить содержимое архива.
    2. Остановить приложение при необходимости.
    3. Сделать текущий бэкап.
    4. Восстановить необходимые файлы.
    5. Проверить права доступа.
    6. Запустить сервисы.
    7. Проверить работоспособность.


============================================================
                    ⏰ AUTOMATION
============================================================

Скрипт можно запускать автоматически через cron.


Пример:

    crontab -e


Ежедневный запуск в 02:00:

    0 2 * * * /opt/spidersoft/scripts/backup.sh \
    /opt/spidersoft/app


Бэкап Docker-конфигурации:

    0 3 * * * /opt/spidersoft/scripts/backup.sh \
    /opt/spidersoft/docker


После настройки cron рекомендуется проверить:

    systemctl status cron


============================================================
                    ⚠️ ВАЖНО
============================================================

Локальный backup не является полноценной
защитой от потери данных.

Если сервер выйдет из строя или будут удалены
одновременно данные и backups/, восстановление
будет невозможно.


Для Production рекомендуется хранить дополнительные
копии:

    Server
       │
       ├──► Local backup
       │
       └──► Remote backup


В будущем можно добавить:

    - автоматическое расписание;
    - retention policy;
    - удаление старых архивов;
    - удалённое хранилище;
    - шифрование;
    - проверку восстановления;
    - мониторинг успешности backup.
